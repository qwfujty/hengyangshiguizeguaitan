# 《恒仰市·规则怪谈》游戏系统与数值设计

> 本文档说明游戏的核心循环、数值系统、商店经济、门槛机制、结局奖励、存档与工程结构。
> 所有数值均可直接在 `data/` 与 `js/` 中修改，修改后运行 `node tools/validate.mjs --strict`
> 与 `node tools/playtest.mjs` 校验。

---

## 1. 设计目标

| 目标 | 实现方式 |
|---|---|
| 读故事，也玩游戏 | 每张地图 = 一条完整视频剧情 + 可交互错误点 + 剧情解说 + 结局解析 |
| 规则即玩法 | 每个原视频的“错误点”变成 2-4 个都合理的选择；选错感染加深/精神下降/体力归零 |
| 有取舍，不逼氪 | 选择次数点通过结局获得；道具永久购买、每局次数重置；不买道具也能通关 |
| 失败也有收获 | 死亡也结算少量选择次数点；规则档案/情绪卡一旦解锁永久保留 |
| 11 张图彼此咬合 | 统一世界观、跨图证物、终章按证物数量改变结局 |
| 可离线、可扩展 | 纯静态 HTML/JS，无构建、无网络依赖；地图数据独立成文件 |

## 2. 核心循环

```
标题 → 安全屋（主页）
        ├─ 补给商店：用选择次数点永久购买道具
        ├─ 地图选择：11 张地图，按四条路线推荐
        ├─ 规则档案 / 恐惧图鉴 / 恒仰市志：收集向
        └─ 进入地图
              ├─ 进图简报：初始数值、携带道具、来源视频
              ├─ 多选推进：感染值 / 精神值 / 体力值 实时变化
              ├─ 道具使用 / 选择记录 / 随时离开（自动存档）
              └─ 结局：死亡 / 溃败 / 异化 / 逃离 / 真相 / 隐藏
                    ├─ 选择次数点结算
                    ├─ 情绪卡、跨图证物、规则档案解锁
                    └─ 剧情解说与复盘（原视频梗概 + 真相 + 世界观）
```

一次典型通关 10-30 分钟；全收集约 10-20 小时。

## 3. 数值系统

### 3.1 三条主数值

| 数值 | 初始 | 范围 | 主要来源 | 归零/满值 |
|---|---|---|---|---|
| 感染值 | 0-35（视地图） | 0-100 | 污染、注视、接触、吃错东西、异变选项 | ≥100：异变结局（成为城市的一部分） |
| 精神值 | 55-82（视地图） | 0-100 | 恐怖、幻觉、亲人异化、记忆冲击 | ≤0：精神崩溃死亡 |
| 体力值 | 70-100（视地图） | 0-100 | 奔跑、熬夜、攀爬、挣扎、即死事件 | ≤0：即死（体力瞬间归零） |

**体力值是本作的核心设计约束：只能下降，没有任何回复手段。**

- 商店不卖体力药，道具效果里 `stamina` 只允许负数（校验器强制）。
- 因此“走到最后”本身就是代价：你走多少路、看多少真相、救多少人，都由初始体力预算决定。
- 设计基准：一条“最稳妥路线”的累计体力损失控制在 25-60；单次损失 ≤25（即死除外）。

### 3.2 数值结算顺序

```
选择 fx → 目标节点 fx
```

任何一步结算后立即判定：体力 ≤0 / 精神 ≤0 / 感染 ≥100 → 进入对应死亡或异变结局。
数值变化会以浮动标签显示（红=感染，蓝=精神，绿=体力），并写入存档。

### 3.3 门槛机制（并非所有选择都能实时触发）

每个选项可以声明门槛：

| 门槛 | 作用 | 示例 |
|---|---|---|
| `items` | 需要持有道具 | 需要「香灰符」才能在后山护住掌心 |
| `infectionMin/Max` | 感染值区间 | 感染 ≥30 才能“听懂”列车员肩章下的影子 |
| `sanityMin/Max` | 精神值区间 | 精神 ≤40 才会出现“和镜中人说话”的疯狂选项 |
| `staminaMin` | 体力下限 | 需要足够体力才能爬通风管 |
| `flags/notFlags` | 剧情伏笔 | 先录下父亲异状，才有“给妈妈看证据”的选项 |
| `evidenceMin` | 跨图证物数量（终章专用） | 至少 6 件证物解锁终章隐藏结局 |
| `hidden: true` | 条件不足时直接不显示 | 让玩家失败后回想“当时好像少了一条路” |

未满足的选项默认显示为灰色锁定；购买「守则批注本」后才显示具体条件，否则只显示“条件不明”。
部分选项被直接跳过（“有些选择，你此刻还触碰不到”；未购买批注本时连这句提示也不显示）。

### 3.4 选项随机与提示信息

- **选项顺序随机**：每次进入一个新节点，引擎会为该节点生成一次随机顺序并写入存档；
  同一节点内重新渲染（打开道具/记录面板）不会再次打乱；读档继续时沿用原顺序。
  键盘数字键（1-9）对应的是界面上的显示序号，而不是数据里的原始序号。
- **提示信息稀有化**：选项的“安全 / 危险 / 代价 / 情感 / 道具 / 即死 / 真相”标签、
  小字提示、锁定原因与“被跳过的选项数量”，属于稀有信息。
  只有永久购买商店道具 **「守则批注本」（100 选择次数点）** 后才会显示；
  未购买时，界面只保留选项正文，玩家必须靠对规则的理解做判断。
- **剧情解说阅读成本**：每次在游戏中展开「剧情解说」，立即扣除 **1 点精神 + 1 点体力**，
  并在面板顶部显示「让我缓缓」。该扣除与节点/选项的数值变化叠加，可能直接导致死亡。
  已收录的解说可在安全屋「剧情解说档案」免费回看，不再消耗数值。

## 4. 选择次数点（CP）经济

### 4.1 获得

| 来源 | 数量 |
|---|---|
| 通关结局（基础） | 死亡 2 / 溃败 4 / 异化 10 / 逃离 14 / 真相 26 / 隐藏 40 |
| 首次非死亡通关本图 | +10 |
| 首次达成真相结局 | +12 |
| 首次达成隐藏结局 | +20 |
| 首次收集情绪卡 | 每张 +2 |
| 结局自定义覆盖 | `ending.cp` 可覆盖基础值（终章 30-55） |

初始赠送 18 点，刚好购买 1-2 件便宜道具，鼓励玩家先体验地图再消费。

### 4.2 消费：补给商店

- 商店道具**永久解锁**，之后每次进入任意地图自动携带；每局使用次数按道具定义重置。
- 道具分四类：回复（精神）、稳定（感染）、护身（一次性挡灾）、事件（解锁选择）。
- **没有体力回复道具**。商店只卖“少走错一步”的东西，不卖“多走一步”的东西。
- 全局商品 25 件，价格 6-100 点；另有 12 件剧情/证物道具只能通过地图获得。

道具带来的游戏体验分三层：

1. **数值道具**（凉白开、香灰符、镇静剂）：直接回复或压制；
2. **事件道具**（旧手机、白纸灯笼、火机、蓝色墨水）：打开原本不存在的选择；
3. **证物道具**（编号牌、副券、登机牌、稳定仪残片）：跨地图通行证，只由真相/隐藏结局授予。

## 5. 结局系统

### 5.1 六种结局类型

| type | 标签 | 含义 | 玩家感受 |
|---|---|---|---|
| `death` | 死亡 | 即死、感染、崩溃、被清理 | 知道自己错在哪（解析给出规则原文） |
| `fail` | 溃败 | 没死，但接受了系统的解释 | 活下来，却不再反抗 |
| `become` | 异化 | 被同化：村民、家族成员、优秀毕业生、安抚员、七七先生 | 温柔、舒适、后知后觉的恶心 |
| `escape` | 逃离 | 活着离开现场，但真相留在原地 | 侥幸，以及“外面还是恒仰市” |
| `true` | 真相 | 看破规则逻辑并带走证物 | 理解，而不是胜利 |
| `hidden` | 隐藏 | 用其他地图的证物/特殊门槛改写结局 | “原来还有这种可能” |

### 5.2 每张地图的结局结构（设计要求）

- ≥4 个结局，其中 ≥2 个死亡、≥1 个真相或隐藏、≥1 个逃离或异化；
- ≥3 条即死路线（内联 `dead` 或直接指向死亡结局节点）；
- 每个结局必须有 2 段以上正文；
- 非死亡结局必须有 ≥3 段解析：原视频梗概 / 角色真相 / 世界观隐喻 / 玩家 choices 复盘；
- 真相 / 隐藏结局授予跨图证物（终章会读取）。

### 5.3 结局奖励与图鉴

- 结局图鉴按地图记录已达成结局（不记录数值型死亡）；
- 每张地图的卡片显示“结局 X / Y”“已通关”“真相已解”；
- 首次通关解锁对应「恒仰市志」条目，逐步补全世界观。

## 6. 收集系统

| 图鉴 | 内容 | 解锁方式 |
|---|---|---|
| 规则档案 | 11 张地图共 213 条守则原文 | 进入对应节点自动解锁 |
| 剧情解说档案 | 295 段剧情解说（原视频故事讲解） | 进入带解说的节点即收录；游戏中展开需消耗 1 精神 + 1 体力 |
| 恐惧图鉴 | 18 类、78 张情绪卡 | 进入节点 / 达成结局 |
| 恒仰市志 | 24 条世界观条目、人物档案、机构说明 | 通关地图后按条件解锁 |
| 结局图鉴 | 每张地图的 138 个结局定义 | 达成结局 |

未解锁的规则、解说与情绪卡以模糊/问号显示，并提示来源地图，鼓励重玩。

## 7. 存档

- 使用浏览器 `localStorage`（键名 `hengyang_rule_horror_save_v1`），**无需服务器**；
- 自动存档：进入每个节点、使用道具、购买商品、结局结算时；
- 中断恢复：地图内可随时点击「离开（保存）」，主页出现“继续探索”；
- 导出 / 导入：设置页可复制存档文本（JSON），换设备/清缓存前备份；
- 清空存档：二次确认；
- 若浏览器禁用 localStorage，首页显示醒目警告，进度仅在当前页面有效。

|---|---|
| 标题 | 世界观引语、点击进入、恐怖题材提示 |
| 安全屋（主页） | 进度概览、继续探索、七个入口（地图/商店/档案/图鉴/市志/说明/设置） |

| 游戏中 | 粘性顶部 HUD（三数值 + 道具/记录/离开）、正文、剧情解说、选项、逐字显示 |
| 结局 | 结局印章、正文、数值、CP 结算、情绪卡/证物、剧情解析与复盘、选择记录 |
| 商店 | 分类商品、价格、永久拥有标记、效果说明 |
| 规则档案 | 按地图/分组展示守则，支持锁定态 |
| 剧情解说档案 | 295 段解说按地图收录，未解锁显示问号 |
| 恐惧图鉴 | 按 18 类分组，卡片含引文与解析 |
| 恒仰市志 | 时间线式世界观条目，逐步解锁 |
| 设置 | 逐字显示、选择提示解锁状态、导出/导入/清空存档 |

交互细节：选项支持键盘数字键 1-9；Esc 关闭弹窗；点击正文可跳过逐字动画；
低精神值时页面轻微抖动（`glitch-on`）。

## 9. 工程结构

```
index.html                  入口（file:// 可直接双击运行）
css/style.css               全部样式（暗色纸墨 + 朱砂 + 旧金）
js/engine.js                引擎：注册表/数值/门槛/道具/结局/存档/图鉴 API
js/ui.js                    界面：11 个屏幕、渲染、事件、逐字动画
data/world.js               世界观元数据、颜色法则、恒仰市志、路线
data/items.js               全局道具（24 商店 + 12 剧情/证物）
data/maps/map01.js … map11.js  11 张地图（每图约 1-3 万字）
tools/load-game.mjs         Node 侧加载真实引擎与数据
tools/validate.mjs          数据校验（结构/引用/门槛/指标/跨图证物）
tools/playtest.mjs          自动试玩（4 种策略 × N 次，检测死锁与平衡）
tools/ui-smoke.mjs          无浏览器 UI 冒烟测试（模拟点击走完全部界面）
tools/gen-docs.mjs          从游戏数据生成剧情总览 / 情绪卡全表 / 道具全表
docs/                       设计文档（本目录）
```

运行方式：双击 `index.html`（或 `启动游戏.bat`）；也可用任意静态服务器托管。

## 10. 质量保障

| 工具 | 命令 | 检查内容 |
|---|---|---|
| 数据校验 | `node tools/validate.mjs --strict` | 11 图齐全、节点/目标/道具/规则引用、体力不回血、结局结构、硬性指标、跨图证物 |
| 自动试玩 | `node tools/playtest.mjs --runs 400` | 随机/稳妥策略、死锁、数值死亡、结局覆盖、稳妥路线可通关 |
| UI 冒烟 | `node tools/ui-smoke.mjs` | 全部屏幕渲染、进图、选择、结局、商店、图鉴、设置、弹窗 |
| 文档生成 | `node tools/gen-docs.mjs` | 由数据生成 `docs/05/06/07`，防止文档与游戏脱节 |

验收标准：validate 0 error、playtest exit code 0、ui-smoke 通过、11 张地图全部可进入。

## 11. 扩展指南

想加第 12 张地图：

1. 复制 `data/maps/map01.js` 为模板；
2. 在 `docs/03-剧本数据规范.md` 的硬性指标内写作；
3. 在 `index.html` 增加 `<script src="data/maps/map12.js"></script>`；
4. 在 `data/world.js` 的 `routes` 里把它归入一条路线；
5. 运行三个工具直到通过；
6. 如需新道具，先在 `data/items.js` 定义全局 id（跨图），否则用本图 `localItems`。

注意事项：

- 不要修改 `js/engine.js` 的既有 API；需要新字段时同时更新校验器与文档；
- 体力值永远不能为正；
- 每个有选项节点至少保留一条无道具门槛的出路；
- 所有死亡都要有“你违反了哪一条”的解析。
